# New Formulation on Real Text-to-SQL Zoo Artifacts

## Conclusion

The closed-form pseudo-label agreement estimator was evaluated on the repository's
saved real model-zoo artifacts. These contain SQL generated by 10 real OpenAI models,
executed result-equivalence classes, source-derived priors, and held-out gold
execution accuracy.

The new formulation does **not outperform** the old estimator overall. More
importantly, neither latent estimator beats the source prior on absolute accuracy.

### Primary results: official train → held-out dev

Only Spider and BIRD have saved priors derived from an official train split and
evaluations on a separate dev split.

| Dataset | Target N | Mean true EX | Source-prior MAE ↓ | Old MAE ↓ | New MAE ↓ | Old Kendall ↑ | New Kendall ↑ |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| Spider dev | 150 | 0.743 | **3.73** | 13.38 | 19.59 | **0.71** | 0.69 |
| BIRD dev | 150 | 0.369 | **3.47** | 17.20 | 16.32 | **0.60** | -0.47 |

The new method is worse than old PoolEval on Spider MAE by 6.21 points. On BIRD it
improves MAE by 0.88 points, but reverses much of the model ordering: Kendall drops
from 0.60 to -0.47 and flip rate rises from 0.20 to 0.73.

### Secondary results: disjoint labeled source slice → held-out target

SQLFlow and BIRD-MiniDev do not have a separate native train artifact in this
pipeline. Their priors use 120 labeled items from a deterministic disjoint source
partition, while evaluation uses 150 held-out target items.

| Dataset | Target N | Mean true EX | Source-prior MAE ↓ | Old MAE ↓ | New MAE ↓ | Old Kendall ↑ | New Kendall ↑ |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| SQLFlow | 150 | 0.424 | **3.82** | 11.28 | 16.38 | **0.72** | -0.67 |
| BIRD-MiniDev | 150 | 0.271 | **2.48** | 13.80 | 20.90 | **0.58** | -0.49 |

On both datasets, the new formulation is worse in absolute accuracy and produces a
substantially reversed ranking.

Spider 2.0-local is excluded from both primary tables. Its tiny-set loader put all
24 usable items in the target while its source prior came from an overlapping tail
slice. Its numbers are retained as a contaminated sensitivity check, not evidence
from a properly held-out evaluation.

## Data and leakage controls

The experiment reuses these saved artifacts:

| Artifact | Prior source | Evaluation target | Separation |
| --- | --- | --- | --- |
| `poolrun_spider.npz` | 120 Spider train questions | 150 Spider dev questions | Official train/dev; database-disjoint |
| `poolrun_bird.npz` | 120 BIRD train questions | 150 BIRD dev questions | Official train/dev |
| `poolrun_sqlflow.npz` | 120-item labeled source partition | 150-item target partition | Deterministically disjoint |
| `poolrun_bird_minidev.npz` | 120-item labeled source partition | 150-item target partition | Deterministically disjoint |
| `poolrun_spider2local.npz` | Small tail slice | All 24 usable local items | **Overlaps; excluded from clean claims** |

For each clean dataset:

- `run.prior` is fixed from source execution accuracy;
- target gold result classes are not passed to either estimator as correctness
  labels—the estimator consumes them only as executed equivalence-class IDs;
- target class `0`, which identifies gold-equivalent execution, is accessed only
  after inference to calculate true EX and pseudo-label diagnostics;
- old and new estimators consume identical target observations;
- the new estimator uses the old estimator's maximum-scoring class as its fixed
  pseudo-label;
- bootstrap resampling changes only target items; the source prior remains fixed.

The artifacts contain previously generated real-model outputs, so this evaluation
requires no new model API calls.

The source prior is the best absolute estimator on every clean dataset. It is also

prior on Spider and SQLFlow but inflates the absolute accuracy level. The new
formulation does not provide a reliable compromise.

## Pseudo-label quality and fitted beta

| Dataset | Actual pseudo-label accuracy | Fitted \(\beta\) | Absolute error | EM iterations |
| --- | ---: | ---: | ---: | ---: |
| Spider | 0.780 | 0.967 | 0.187 | 184 |
| SQLFlow | 0.487 | 0.226 | 0.261 | 155 |
| BIRD | 0.453 | 0.210 | 0.243 | 113 |
| BIRD-MiniDev | 0.327 | 0.278 | 0.048 | 200 |

The old scorer selects a genuinely correct executed result on 78% of Spider items,
but fewer than half the items on the harder datasets. This is a candidate-coverage
limitation: if no model produces the gold result, a pseudo-label chosen from model
outputs must be wrong.

The fitted \(\beta\) is not a calibrated estimate of pseudo-label accuracy. It is
too high on Spider and too low on SQLFlow/BIRD. BIRD-MiniDev's aggregate \(\beta\)
is closer, but its per-model accuracies and ranking are still wrong.

## Paired item-bootstrap uncertainty

Each dataset uses 500 paired target-item bootstrap resamples. The interval below is
the percentile 95% interval for `new − old`.

| Dataset | ΔMAE, new − old | ΔFlip | ΔKendall |
| --- | ---: | ---: | ---: |
| Spider | **+5.86 [3.65, 7.83]** | +0.009 [-0.044, 0.067] | -0.029 [-0.136, 0.061] |
| SQLFlow | +6.69 [-0.73, 15.71] | +0.523 [-0.022, 0.822] | -1.075 [-1.674, 0.045] |
| BIRD | -0.67 [-8.90, 9.47] | **+0.476 [0.122, 0.767]** | **-0.973 [-1.578, -0.247]** |
| BIRD-MiniDev | +8.40 [-0.13, 15.70] | **+0.448 [0.067, 0.689]** | **-0.912 [-1.393, -0.128]** |

The Spider MAE degradation is stable. BIRD and BIRD-MiniDev ranking degradation is
also stable. SQLFlow intervals are unusually wide because bootstrap samples can
move the binary likelihood between very different solutions.

Bootstrap intervals describe uncertainty from the finite target item set. They do
not cover uncertainty from model-pool choice, generation randomness, dataset
selection, or source-prior construction because only one saved zoo run exists per
dataset.

## Failure mechanism

### 1. Multiclass wrong answers violate the binary conditional model

The new formulation assumes

\[
P(C=1\mid Z=0)=1-\beta.
\]

For Text-to-SQL, a wrong model and a wrong pseudo-label need not produce the same
wrong result. There may be many executable but incorrect result tables. Thus the
probability of agreement when both are wrong is much smaller and depends on error
concentration, model provenance, and the question.

The EM compensates by moving \(\alpha\) and \(\beta\) to extreme or misleading
values. On Spider, estimated model accuracies range from 0.85 to nearly 1.00 even
though true EX ranges from 0.69 to 0.80. On BIRD, the strongest model is estimated
near 0.13 while weaker models receive estimates above 0.40.

### 2. The likelihood has a complement symmetry

The marginal agreement probability is

\[
P(C=1)=\alpha_j\beta+(1-\alpha_j)(1-\beta).
\]

Replacing \((\alpha_j,\beta)\) by
\((1-\alpha_j,1-\beta)\) leaves this probability unchanged. A train-derived prior
used only as initialization cannot identify the absolute orientation after the EM
updates begin. This is especially dangerous when both model and pseudo-label
accuracy are around or below 0.5, as on the harder benchmarks.

### 3. The pseudo-label inherits the old method's coverage ceiling

The new method's pseudo-label is selected from classes produced by the pool. When
every model is wrong, the correct class is absent. The new binary EM cannot create a
missing result class; it can only reinterpret agreement with a necessarily wrong
pseudo-label.

These results must not be described as held-out because the saved source slice
overlaps the target. The enormous \(\beta\) error—0.958 estimated versus 0.125
actual—still illustrates the likelihood problem, but not under a clean protocol.

## Recommendation

Do not replace old PoolEval or the source prior with the current binary formulation.
For these real artifacts, the simplest source-prior baseline is the strongest
absolute estimator.

A defensible next formulation needs at least:

1. a separate wrong-result collision parameter
   \(\gamma=P(r=\hat y\mid Z=0,\hat y\ne y)\);
2. an identifying anchor that remains in the objective, such as a Beta prior over
   every \(\alpha_j\), rather than using source accuracy only for initialization;
3. provenance-dependent or pair-dependent collision probabilities;
4. an explicit missing-candidate mechanism or judge for items where every model is
   wrong.
